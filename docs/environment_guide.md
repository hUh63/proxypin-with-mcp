# 环境变量指南

环境变量用于在请求、重写规则中动态替换值，实现一套接口多环境切换、动态参数等能力。

## 基本语法

在任意请求参数、请求头、重写规则内容中使用 `{{变量名}}`：

```
https://api.example.com/user?token={{token}}
Authorization: Bearer {{token}}
```

请求发出时会把 `{{token}}` 替换为当前环境的变量值。

## 创建与切换

1. 「设置 → 环境变量」进入环境列表；
2. 新建环境（如「开发」「测试」「生产」），每个环境里维护各自的变量；
3. 顶部切换当前生效的环境；
4. 请求与重写规则中的 `{{变量名}}` 会自动使用当前环境的值。

## 变量作用域

- **环境变量**：只在对应环境激活时生效；
- **全局变量**：任何环境下都生效，环境变量优先级更高。

## 内置通用变量

无需定义，直接使用（每次请求实时计算）：

| 变量 | 示例值 |
|---|---|
| `{{timestamp}}` | 秒级时间戳 `1725000000` |
| `{{timestamp_ms}}` | 毫秒级时间戳 `1725000000000` |
| `{{datetime}}` | ISO 时间 `2024-08-30T10:00:00.000` |
| `{{date}}` | 日期 `2024-08-30` |
| `{{time}}` | 时间 `10:00:00` |
| `{{uuid}}` | UUID v4 随机串 |
| `{{unix_date}}` | 自 1970 年以来的天数 |

同名自定义变量会覆盖内置变量。

界面上不用记这些名字：环境变量页面右上角的 **⚗（内置变量）** 按钮会列出全部内置变量，点一下就能复制 `{{变量名}}` 到剪贴板。

## 使用建议

- token、签名等易变值放环境变量，避免硬编码在重写规则里；
- 多环境接口地址也可做成变量：`{{host}}/api/user`；
- 变量未定义时会原样保留 `{{xxx}}`，方便发现漏配。
