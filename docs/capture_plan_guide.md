# 采集方案（Capture Plans）

> 把「一次抓包任务」沉淀成可复用模板：一组**包含 / 排除域名规则**，加一份**人工操作步骤清单**。
> 一键把域名规则应用到「域名过滤」，让抓包只聚焦目标业务。
> 入口：工具箱 → **采集方案**。

---

## 1. 是什么，解决什么问题

抓包时最耗时的两件事：

1. **噪音多**：一次点击可能触发几十上百个请求，真正的业务接口淹没在统计、广告、埋点里。
2. **任务不可复用**：这次抓 A 功能，下次还要重新回忆"该过滤哪些域名、先做哪几步"。

采集方案把这两件事一次性固化下来：

- **域名规则**（包含 / 排除）→ 一键写入「域名过滤」的白名单 / 黑名单；
- **操作步骤** → 下次抓同一类任务时照着走，不用凭记忆。

它是一份**模板 / 备忘录**，不改变抓包引擎的行为：方案本身**不会**自动操作目标 App、重放接口、或改写线上数据。

---

## 2. 与「域名过滤」的关系

这是最容易混淆的一点，先讲清楚：

| | 采集方案 | 域名过滤（白名单 / 黑名单） |
|---|---|---|
| 作用 | 保存一组域名规则的**模板** | 真正决定**哪些请求被抓取** |
| 生效方式 | 点「应用到域名过滤」后才写入过滤器 | 立即生效 |
| 存储 | `capture_plans.json` | 应用配置里的 `whitelist` / `blacklist` |

点「应用到域名过滤」时发生的事：

1. **包含域名**逐条写入**白名单**，并把白名单开关打开；
2. **排除域名**逐条写入**黑名单**，并把黑名单开关打开；
3. 调用 `Configuration.flushConfig()` 立即持久化，重启后依然有效。

> 白名单一旦非空，**不在白名单里的请求都会被过滤**——这正是"只抓目标域名"的语义。
> 如果你只想排除少数域名、其余全抓，就**只填排除域名**，不要填包含域名。

## 3. 使用方法

### 3.1 打开

- **桌面端**：工具箱 → 采集方案（独立窗口）；
- **移动端**：工具箱 → 采集方案（页面跳转）。

### 3.2 新建 / 编辑方案

点右上角「新建方案」，或卡片菜单里的「编辑」：

| 字段 | 说明 |
|---|---|
| 方案名称 | 必填，仅作标识 |
| 来源应用 | 选填，例如「某某 App」，方便日后辨认 |
| 方案说明 | 选填，写清这个方案要抓什么 |
| 包含域名 | 一行一个（也支持逗号 / 分号分隔），如 `*.example.com` |
| 排除域名 | 同上，优先级高于包含 |
| 操作步骤 | 每步一个「标题 + 说明」，可增删排序 |

域名规则语法：

- `example.com` —— 精确匹配该主机；
- `*.example.com` —— 匹配 `example.com` 及其所有子域；
- 无 `<` / `>` 之类的正则符号要求，非法的写法（含空格、斜杠、冒号等）会被**自动忽略**，不会写入。

### 3.3 应用到域名过滤

卡片菜单 →「应用到域名过滤」。成功后域名过滤即时更新，可到「设置 → 域名过滤」核对。

### 3.4 复制 / 导出 / 删除

- **复制**：以当前方案为基础生成副本，适合派生多个变体；
- **导出**：把方案保存为 `*.capture-plan.json`，便于团队间传递或纳入版本管理；
- **删除**：内置方案会随应用重新补齐，自定义方案删除后不可恢复。

### 3.5 启用开关

每张卡片右侧的开关用于标记"这个方案我正在用"（`enabled`），纯属管理用途，不参与抓包逻辑。

## 4. 内置方案

| 方案 | 用途 |
|---|---|
| 移动端 App 抓包排查 | 从确认代理连通性到定位目标 App 请求的完整流程 |
| 接口清单梳理 | 走完一个功能的全部请求，再导出接口清单 |

内置方案**不含具体业务域名**（避免误导），需要你在「包含域名」里补上自己的目标域名。

## 5. 实现细节（开发）

### 5.1 数据模型

文件：`lib/network/components/manager/capture_plan_manager.dart`

```
CapturePlanStep { id, title, description }
CapturePlan {
  schemaVersion, id, name, appName, description,
  enabled, builtIn,
  includeDomains: List<String>, excludeDomains: List<String>,
  steps: List<CapturePlanStep>
}
```

- `CapturePlan.currentSchemaVersion` 用于未来迁移；
- `matchesHost(host)` 用 `CaptureDomainMatcher` 判断某主机是否落在方案范围内；
- `toJson / fromJson` 保证字段缺失时的容错（未知字段忽略、`enabled` 默认 `true`）。

### 5.2 域名匹配

`CaptureDomainMatcher`：

- `normalizePattern` —— 转小写、去首尾点、Trim；
- `isValidPattern` —— 只接受合法的域名 / 通配写法；
- `matches(host, include, exclude)` —— 先要求命中包含，再要求未被排除命中；
- `toHostPattern` —— 转成域名过滤器接受的写法。

> 写入域名过滤器时，`*` 由 `HostList.add()` 统一展开为正则 `.*`，与「域名过滤 → 导入」的既有行为保持一致，避免同一份规则在两处语义不同。

### 5.3 管理器

`CapturePlanManager extends ChangeNotifier`（与 `EnvironmentManager`、`NetworkConditionManager` 一致）：

- `instance` —— 异步单例，首次访问时加载；
- `plans` —— 只读列表（含内置）；
- `add / update / remove / setEnabled / byId` —— 增删改查，每次变更后写盘并 `notifyListeners()`；
- `static applyToFilter(plan, {configuration})` —— 写域名过滤器 + `flushConfig()`。

持久化位置由 `Paths.getPath('capture_plans.json')` 决定：桌面便携模式下跟随程序目录的 `proxypin_data`，否则在系统应用支持目录——与历史记录、配置的口径一致。

### 5.4 页面

文件：`lib/ui/component/capture_plan_page.dart`

- 卡片列表 + 展开步骤，全部文案走 `AppLocalizations`（`capturePlan*` 键）；
- 编辑对话框是独立 StatefulWidget，域名解析集中在 `_parseDomains` / `_invalidDomains`；
- 导出沿用 `FilePicker.saveFile(fileName:, bytes:)`（file_picker 12.x 静态 API）。

### 5.5 入口接线

| 位置 | 代码 |
|---|---|
| 工具箱 | `lib/ui/toolbox/toolbox.dart` → `IconText(... capturePlan ...)` |
| 桌面多窗口 | `lib/ui/component/multi_window.dart` → `'CapturePlanPage'` 分支 |

同类页面（如网络诊断）也走同样的两条路径，新增页面时**两处都要加**，否则桌面端点击无反应。

## 6. 与其他功能的联动

- **域名过滤**：方案是它的规则来源之一（写入白名单 / 黑名单）；
- **应用筛选**：配合使用可进一步缩小范围（先按 App 过滤，再按域名过滤）；
- **API 端点**：域名过滤生效后，从更干净的请求集里提取端点，导出的 OpenAPI / Postman 更准；
- **历史记录**：抓包过程会自动归档；方案负责"抓什么"，历史负责"抓过的存证"；
- **MCP / 自动化**：MCP 侧的抓包查询支持按 domain 过滤，可与方案圈定的域名范围对应。

---

## 7. 边界与安全定位

采集方案刻意**不提供**任何"操作目标"的能力：

- 不自动点击、不自动发请求、不重放、不改写数据；
- 不做漏洞探测 / 攻击载荷投递 / 绕过检测。

它只回答一个问题：**"这次我要抓哪些域名的请求？"**
这是调试代理该有的中立性。

## 8. 常见问题

**Q：点了「应用到域名过滤」，其他 App 的请求都不见了？**
A：因为你填了包含域名，白名单已启用。清空包含域名，或到「域名过滤」关闭白名单开关即可。

**Q：内置方案能删吗？**
A：可以，但下次启动会重新补齐。想保留自己的修改，直接编辑内置方案即可（修改会被持久化）。

**Q：导出的 `.capture-plan.json` 能导回来吗？**
A：当前版本支持导出、不支持导入；需要迁移时手工新建方案并粘贴域名即可。

**Q：域名写错了会怎样？**
A：非法写法（含空格、斜杠等）在保存时被静默忽略，不会污染过滤器。
