# 手动 Fuzz（变体发送）

> 把**你自己写的取值**逐条替换进一条请求发送，把每条响应摆在一起对照。
> 取值可以手填、从**字典**导入或用**脚本**生成；发完能按你配的规则自动标出和基线不一样的条目。
> 入口：工具箱 → **手动 Fuzz**。

---

## 1. 定位（重要）

它做的是**重复劳动的自动化**，不是"漏洞扫描器"：

| 做 | 不做 |
|---|---|
| 用你填的取值逐条替换并发送请求 | ❌ 不提供成套攻击载荷库（内置仅 22 条边界值种子） |
| 多个位置可同时注入，跑它们的**组合** | ❌ 不自动判定"是否存在漏洞" |
| 记录每条的状态码、耗时、长度、响应体 | ❌ 不自动利用、不自动扩大范围 |
| 与基线请求做事实差异，可按你配的规则自动标出 | ❌ 不给"高危/安全"之类的结论 |
| 结果批量导出 CSV / JSON 留证 | ❌ 不内置结论字段（评级、风险等级） |

**结论由你下**——工具只负责把"发 100 次并逐条记录"这件事做干净。

> 只对**你自己的应用**或**已获授权**的目标使用。

---

## 2. 基本用法

1. 工具箱 → **手动 Fuzz**；
2. 选一条**模板请求**（取自当前抓包列表，最多列最近 300 条）；
3. 在「注入项」里选**注入位置**并填字段：

| 注入位置 | 填什么 | 效果 |
|---|---|---|
| URL 查询参数 | 参数名（如 `id`） | 把该参数的值替换为取值 |
| 请求头 | 头名（如 `Referer`） | 把该头的值替换为取值 |
| JSON 请求体字段 | 字段名 | 解析 JSON、替换该字段值后重新编码 |
| 请求体占位符 | 占位符（默认 `{{FUZZ}}`） | 把请求体里的占位符整体替换 |

4. 在「取值」框里一行填一个（`#` 开头的行会被忽略），或点「**从字典填充**」一键灌入（见第 4 节）；
5. 可选「**先发基线**」：先原样发一次原始请求，后续每条都会和它对比；
6. 「间隔」控制两条之间的等待（默认 200ms，避免把目标打爆）；
7. 点「开始」，结果会逐条追加；随时可「停止」。

---

## 3. 多参数组合（笛卡尔积）

一条注入项只能验证"一个位置换不同取值"。想看**两个位置一起变**的效果，就再加一条注入项：

1. 点右上角「**添加注入项**」，出现第 2 张卡片；
2. 例如：

   | 注入项 | 位置 | 字段 | 取值 |
   |---|---|---|---|
   | 1 | URL 查询参数 | `page` | `1` `2` `3` |
   | 2 | 请求头 | `X-Tenant` | `a` `b` |

3. 标题右侧的「**组合数**」会实时显示总条数（这里是 3 × 2 = 6）；
4. 点「开始」，6 条变体请求依次发出，每条的**取值列**显示它的完整组合标签：

   ```
   page=1 & X-Tenant=a
   page=1 & X-Tenant=b
   page=2 & X-Tenant=a
   ...
   ```

**上限**：组合总数最多执行 **500** 条。超了会提示并只跑前 500 条（避免一次点下去把目标打爆、也避免把内存跑满）。要缩小范围就先减少某条注入项的取值个数。

删除注入项：点该项右侧的 ➖（只剩一条时不可删）。

## 4. 取值从哪来：字典

除了在「取值」框里手打，还可以用**字典** —— 一组预存好的取值，一键灌进某个注入项。

点注入项卡片上的「**从字典填充**」，选一个字典，它的取值就按行填进取值框（**追加**，不覆盖你已填的）。

字典有三种来源：

| 来源 | 怎么来 | 适合 |
|---|---|---|
| **内置** | 出厂自带「边界值 / 类型异常」（22 条，只读） | 快速试后端对异常输入的处理 |
| **手填 / 导入** | 自己一行一条，或从 `.txt` / `.csv` 按行导入 | 你的业务取值、一批 ID、一批路径 |
| **脚本生成** | 写一段 JS，把结果数组赋给 `result` | 有规律的批量取值 |

**内置字典里是什么**：空串、空格、`null`、`undefined`、`0`、`-1`、超长数字、`NaN`、`[]`、`{}`、
单双引号、`<b>`、`&`、`%00`、`../`、反斜杠、一长串 `A`……
都是「输入校验测试」的起点，**不是攻击载荷**。

**脚本字典怎么写**：

```js
// 结果数组赋给 result，工具读它
result = ['a', 'b', 'c'];

// 按规律生成
result = Array.from({length: 8}, (_, i) => 'x'.repeat(i + 1));

// 1 到 50
result = Array.from({length: 50}, (_, i) => String(i + 1));
```

脚本在本地 JS 引擎里跑，**不联网**。跑完把 `result` 转成字符串列表；执行报错会提示，不会静默吞掉。

> 内置字典只读，想改就复制一份出来改。用户字典存在本地，下次打开还在。

## 5. 自动判定：与基线比什么

发了 100 条，一条条肉眼比对太累。「**判定规则**」面板让工具自动把**值得看的**标出来。

一共 5 条规则，**默认只开第 1 条**：

| 规则 | 在比什么 | 默认 | 参数 |
|---|---|---|---|
| **请求失败** | 连不上 / 超时 / 被中断 | ✅ 开 | — |
| 状态码变化 | 与基线的状态码不同 | 关 | — |
| 长度明显变化 | 响应体长度差超过阈值 | 关 | 百分比，默认 20% |
| 响应明显变慢 | 比基线慢超过阈值 | 关 | 毫秒，默认 500 |
| 命中关键字 | 响应体出现你指定的词 | 关 | 关键字，**留空不生效** |

命中的结果行会挂上标签，例如「长度明显变化（20%）」「命中关键字（error）」。

**为什么默认只开第一条**：只有「请求失败」是客观异常，其余每条的阈值都得看你的业务 ——
关键字的词、长度的百分比，都得你自己定，**填了才生效**。

> 规则只回答一个问题：「这条**和基线不一样**」。
> 它**不**回答「这里有没有漏洞」——不下「高危 / 安全」的结论，也不预置任何漏洞特征串。
> 口径完全由你的参数决定。配置会记住，下次打开还在。

## 6. 结果导出（留证）

结果区右上角的 **⬇** 按钮可把当前所有结果导出：

| 格式 | 内容 | 适合 |
|---|---|---|
| **CSV** | `index, payload, baseline, status, length, duration_ms, diff, error` 一行一条 | 丢进 Excel 排序筛选、贴进报告 |
| **JSON** | 生成时间、模板请求、总条数、逐条结构化结果 | 脚本二次处理、归档留证 |

- 带 `,` `"` 换行的字段会自动加引号转义，CSV 不会串列；
- 导出的是**当前列表里的全部结果**（含基线那一行，`baseline=1` 标记）；
- 导出前先「停止」，结果还在变动时按钮不显示。

---

## 7. 结果怎么读

每行显示：序号、取值、状态码、响应长度、耗时，下面是**与基线的差异**：

```
状态 200 → 500，长度 +1204
耗时 +320%
```

若命中了第 5 节的判定规则，行上会带标签（如「状态码变化」「命中关键字（error）」）。

差异只陈述**事实**（状态变了、长度变了、耗时差多少），不解释为"存在漏洞"。

点任意一行可查看该条的完整响应体，支持一键复制。

## 8. 实现细节（开发）

`lib/network/util/request_fuzzer.dart`

- `FuzzInjection` —— 一个注入项（位置 + 字段 + 占位符 + 取值列表）；
- `buildCases(injections, {limit})` —— 对多个注入项做**笛卡尔积**，产出 `FuzzCase`（`values` + 展示用 `label`），超过 `maxCombinations`（500）截断；
- `combinationCount(injections)` —— 组合总数，供界面实时预览；
- `buildVariant(template, injections, values)` —— 克隆模板请求（method / uri / headers / body），依次套用每个注入项，得到一条变体；
- `send(request, ...)` —— 复用项目的 `HttpClients.proxyRequest(...)`（与「重放」同一条链路，因此外部代理、超时策略一致）；
- `diffOf(baseline, current)` —— 产出事实差异文案；
- `toCsv(results)` / `toJson(results, template:)` —— 结果导出；
- `parsePayloads(text)` —— 一行一个，忽略空行与 `#` 注释；
- `FuzzAnomalyRule` / `FuzzAnomaly`（同文件）—— 基线与变体的自动比对。`defaults()` 定义 5 条规则（只开「请求失败」），`match(outcome, baseline, rules)` 返回命中的规则名，`encode` / `decode` 负责持久化（key `fuzz_anomaly_rules_v1`）。

字典：`lib/network/util/fuzz_dictionary.dart`

- `FuzzDictionary` —— 一个字典（`name` + `entries` + 可选 `script` + `builtin` 只读标记）；
- `FuzzDictionaryStore.builtinSeeds` —— 22 条边界值 / 类型异常种子；
- `FuzzDictionaryStore.load()` / `save()` —— 用户字典持久化（key `fuzz_dictionaries_v1`，整体覆盖，内置不入库）；
- `FuzzDictionaryStore.runScript(script)` —— 跑 JS，读全局 `result` 数组，转字符串列表（`flutter_js`，`xhr: false`）；
- `FuzzDictionaryStore.resolve(dict)` —— 展开一个字典的全部取值（静态条目 + 脚本产物，去重保序）。

字典管理界面：`lib/ui/component/fuzz_dictionary_dialog.dart`。

页面：`lib/ui/component/fuzzer_page.dart`（接收当前请求列表；`Navigator.push` 打开；导出用 `FilePicker.saveFile`）。

限制：

- 模板列表最多 300 条（取最近的）；
- 单次最多 500 个组合；
- 单条响应体最多保留 256 KB 供查看；
- 单请求超时 15 秒。

## 9. 与其他功能联动

- **断点**：先用断点看清请求结构，再来 Fuzz；
- **重写 / 脚本**：Fuzz 结果里发现有意思的响应，可用重写规则固化下来复现；
- **对比**：与「请求对比」功能搭配，可把两条具体响应逐字段 diff；
- **安全自检**：Fuzz 是"主动发送任意取值"，安全自检默认是"被动分析已抓流量"（可选的主动核验也只对已抓到的域名各发一次 GET 看安全响应头）——两者边界不同，别混用。

## 10. FAQ

**Q：能直接扫描 SQL 注入 / XSS 吗？**
A：不能，也不会做。本工具不内置攻击载荷、不自动判定漏洞 —— 规则只标「和基线不一样」。
你可以用**自己填、导入或用脚本生成的取值**去看响应差异，发什么由你决定，结论也由你下。

**Q：会不会把目标打崩？**
A：间隔默认 200ms，建议不要调太小；组合数上限 500；目标是自己或已授权资产时再上线。

**Q：结果能导出吗？**
A：可以。结果区右上角 ⬇ 可选 **CSV**（进表格统计）或 **JSON**（结构化留证）。

**Q：字典里是不是藏了攻击载荷？**
A：没有。内置的只有 22 条边界值 / 类型异常串（空值、超长、特殊字符这些）。
发什么取值由你自己填、导入或写脚本算 —— 工具不提供成套的、拿来就能打的载荷库。

**Q：规则标红了，是不是就有漏洞？**
A：不是。规则只说明「这条响应和基线不一样」，比如长度差了、状态码变了。
是不是问题、是什么问题，得你自己看响应内容判断。

**Q：为什么加了两条注入项，组合数还是原来的？**
A：组合数只统计**填了取值**的注入项；某条注入项取值框是空的，它就不参与组合。
