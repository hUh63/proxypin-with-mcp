# HTTPS 抓不到 / 应用报「无网络」排查指南

> 这类问题的表现很像"网络坏了"，其实绝大多数是**证书信任**在某一层被拒绝了。
> 本工具能自己识别出是哪一层：工具箱 → **抓包自检**（AI 也可调 `diagnose_capture`，结果同源）。

---

## 1. 先分清是哪一层

```
应用报无网络 / HTTPS 抓不到
│
├─ 第 0 层：流量根本没进来
│    · 代理服务没启动 / 系统代理没指向本工具 / 移动端 VPN 没开
│    → 自检直接报 error
│
├─ 第 1 层：系统不信任本工具的 CA
│    · Android 7 起，应用默认不信任「用户安装的证书」
│    · 桌面端根证书没装进系统受信任根
│    → 表现：成片的握手失败 / 感叹号包
│    → 自检会区分证书装在「系统库」还是「只在用户库」
│
└─ 第 2 层：应用不信任「任何」本机安装的证书（证书固定 / SSL Pinning）
     · 应用把服务端证书或公钥写死在代码里，只认那一个
     · 或应用自带根证书列表（如 Flutter 的 Dart 网络栈），根本不读系统 CA
     → 表现：隧道能建立（CONNECT 成功），但内容永远是空的
     → 自检会列出「只隧道不解密」的域名，判为「SSL 证书固定（疑似）」
```

关键区别：第 1 层是"系统不信任"，第 2 层是"应用不信任何"。**装证书能解决第 1 层，解决不了第 2 层。**

---

## 2. 第 1 层的解法

| 环境 | 做法 |
|---|---|
| Android（有 root）| 把 CA 装进**系统**信任库。Android 14+ 的路径是 `/apex/com.android.conscrypt/cacerts`；也有现成的 Magisk 模块可以把用户库证书搬进系统库 |
| Android（无 root）| 给目标应用配 `network_security_config`（需要能改那个应用，或在其开发阶段就加上）；或用支持"应用转生"的虚拟机方案 |
| Android（自己开发的应用）| 在 `res/xml/network_security_config.xml` 里加 `<debug-overrides>` 以信任用户证书 |
| Windows | 「HTTPS 证书」页把根证书装到「受信任的根证书颁发机构」 |
| macOS / iOS | 安装后还要**手动勾选信任**（iOS 需在「关于本机 → 证书信任设置」里打开开关）|

自检会直接告诉你是装在了系统库还是用户库，以及该往哪一步走。

---

## 3. 第 2 层的解法

第 2 层是应用主动校验，没有"改个配置就好"的办法，必须做**运行时干预**：

| 方案 | 说明 | 前提 |
|---|---|---|
| hook 框架 + 证书固定绕过模块 | 最常见的一条路。例如 LSPosed（基于 Zygisk/Magisk）配合 TrustMeAlready 这类开源模块，只对勾选的应用生效 | 需要 root + LSPosed 环境 |
| 应用转生 / 虚拟机方案 | 免 root，把目标应用"转生"进虚拟环境，在环境内加载 hook 模块 | 免 root，但需要重装目标应用的改造版 |
| Frida 脚本 | 直接 hook 校验函数，灵活度最高 | 需要 root 或可调试的应用；脚本要针对具体实现写 |
| 逆向后打补丁 | 改掉校验逻辑再重打包 | 成本高，通常只用于分析自己拥有的应用 |

**请务必注意**：以上都属于对目标应用的**运行时干预**。只应在

- 你自己拥有的设备上，并且
- 你对目标应用有测试授权（自己的应用，或明确取得书面授权的目标）

的前提下使用。未经授权对第三方应用做这类操作，可能违反其用户协议甚至相关法律。

## 4. 本工具做什么 / 不做什么

**做**：把这套排查逻辑内置成自检。用你**已经抓到的流量**判断问题出在哪一层，省掉"到底哪里错了"的反复猜测。

**不做**：不内置、不打包、不捆绑任何 hook 模块或绕过工具。那些是独立 APK，要装在 Xposed/LSPosed 环境里，与本工具是**并列关系**。我们只做**诊断与说明**，不做运行时干预。

## 5. 常见误判

**Q：应用提示"网络连接失败"，一定是被拦了吗？**
不一定。先看自检——如果第 0 层就是 error（代理没开、流量没进来），应用当然没网络。先把第 0 层修好再看。

**Q：浏览器能正常上网，只有某个应用不行。**
典型的第 2 层。浏览器走系统信任库，所以认本工具的证书；那个应用自己校验，不认。

**Q：证书明明显示"已安装"，为什么还是抓不到？**
看自检的「CA 根证书」项。Android 上"已安装"和"被应用信任"是两件事——装在用户库的证书，绝大多数应用不会去读。

**Q：Flutter 应用为什么特殊？**
Flutter 的 Dart 网络栈带自己的根证书列表，默认完全不读系统 CA。所以第 1 层和第 2 层对它都不适用，需要单独的绕过手段。

**Q：自检没报「SSL 证书固定（疑似）」，是不是就说明没有 Pinning？**
不一定。这一项只有在**证书已正确安装**、并且你**已经抓到过该域名的流量**时才会判断。刚启动还没流量时它不会出现——先抓一段再回来看。
