# 请求重写指南

请求重写可以按规则自动改写请求或响应，无需写代码。适合固定 mock、改参数、重定向等高频操作。

## 规则类型

| 类型 | 作用 |
|---|---|
| 替换请求 | 把匹配请求的 URL 整体替换为新 URL |
| 修改请求 | 按 key 替换或追加请求头 / 查询参数 / 请求体片段 |
| 替换响应 | 直接返回自定义响应（可自定义状态码与响应体） |
| 修改响应 | 按 key 替换响应头 / 响应体片段 |
| 重定向 | 把请求重定向到另一个地址，可配合 `*` 通配符 |

## 创建规则

1. 「设置 → 请求重写」进入规则页；
2. 点击右上角 + 新建规则；
3. 填写匹配 URL、选择规则类型、填写修改内容；
4. 打开规则开关后立即生效。

## URL 匹配语法

- 精确匹配：`https://example.com/api/user`
- 通配符匹配：`https://example.com/api/*`，星号匹配任意后缀
- 重定向规则双方都可用 `*`，转发时会保留通配部分：

```
匹配：https://a.com/api/*
重定向：https://b.com/api/*
请求 https://a.com/api/user  →  https://b.com/api/user
```

## 修改内容的 key/value

「修改请求 / 修改响应」按 key 定位、value 替换：

- 修改请求头：key 填 `user-agent`，value 填新值；
- 修改请求体 JSON：key 填字段名，value 填新值；
- value 留空表示删除该 key。

## 正则匹配与分组引用

key 支持正则（打开规则里的「正则」开关），value 里用 `$0`~`$99` 引用捕获分组：

| 写法 | 含义 |
|---|---|
| `$0` | 整段匹配到的文本 |
| `$1` `$2` … | 第 1、2… 个捕获分组 |
| `${12}` | 分组号 ≥ 10 时用花括号包住（写 `$12` 也识别） |

例：修改响应体，key 填 `"token":"(\w+)"`，value 填 `"token":"$1-signed"`。

- 分组引用在**修改响应体 / 修改请求体 / 修改响应头 / 修改请求头 / 修改参数**里都生效；
- 越界引用（正则里只有 1 个分组却写了 `$2`）会**原样保留**，方便对照检查写法；
- 分组内容本身含 `$1` 这类文本时不会被二次替换。

## 环境变量支持

规则内容支持 `{{变量名}}` 语法，替换时会实时渲染环境变量：

```
redirectUrl 填：https://test.com/api?ts={{timestamp_ms}}
```

配合内置变量（`{{timestamp}}`、`{{uuid}}`、`{{date}}` 等）可实现每次请求自动变化，详见「使用文档 → 环境变量指南」。

## Mock 场景合集（一键批量启停）

规则的「场景」字段用于把多条规则归为一组，方便在不同调试场景之间整组切换。

1. 编辑规则时，在「场景」输入框填场景名（新建，或从下拉里选已有名字），保存即完成归类；留空表示未归类。
2. 在「请求重写」页点「Mock 场景」按钮：
   - 开关：整组启用 / 停用；
   - 仅启用：只启用该组，其余全部停用；
   - 重命名：整组改名；
   - 移出分组：解除归类（规则保留，不会被删除）。
3. 场景名写进规则配置（`request_rewrite.json` 的 `scenario` 字段），随导入 / 导出 / 分享一起流转。

典型用法：为「成功响应」「超时 / 异常」「空数据 / 边界」各建一个场景，联调时点「仅启用」一键切到对应分支，不必逐条改开关。

## 使用建议

- 规则过多时按域名整理并只在需要时打开开关；
- 重写不生效时优先检查 URL 匹配串是否带多了参数；
- 排查时可在请求详情查看「重写」标记确认命中。
