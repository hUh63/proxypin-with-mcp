# 快速上手

> 5 分钟学会用 ProxyPin 抓包

## 什么是 ProxyPin

ProxyPin 是一款开源免费的跨平台抓包工具，支持 Windows / macOS / Linux / Android / iOS。它可以拦截、查看、修改、重放 HTTP(S) 流量，是接口调试与问题排查的利器。

各平台的能力边界见文末「平台支持边界」。

## 三步开始抓包

### 第一步：安装证书（HTTPS 必需）

==HTTPS 流量是加密的，ProxyPin 需要安装并信任 CA 证书才能解密查看==：

1. 打开 ProxyPin，进入「设置」→「HTTPS 抓包」，确认抓包开关已开启
2. 按平台安装证书：
   - **Android**：设置 → 「下载证书」或「导出证书」，然后在系统设置中安装 CA 证书（部分机型需要在「加密与凭据」中安装）；Root 设备可将证书装入系统目录
   - **iOS**：Safari 访问代理下载页安装描述文件，并在「设置 → 通用 → 关于本机 → 证书信任设置」中开启完全信任
   - **桌面端**：首次启动会引导安装根证书（Windows 需确认弹窗；macOS 需在钥匙串中设置信任）
3. 详细的分平台步骤见「证书与 HTTPS 抓包」文档

### 第二步：让设备流量走代理

- **桌面端**：设置中开启「系统代理」，浏览器/应用流量自动经过 ProxyPin
- **Android**：手机与电脑连同一网络，在 WiFi 高级设置中配置手动代理，主机填电脑 IP、端口填 ProxyPin 显示的端口；也可以用手机版 ProxyPin 直接抓本机（VPN 模式）
- **iOS**：WiFi 代理配置同上

提示：桌面端工具箱里有「二维码」工具，手机扫码即可快速配置代理，无需手动输入。

```json
<!--demo:演示手机扫码配置代理的二维码内容格式，用任意二维码工具生成后扫码即可连接-->
{"type": "proxy", "host": "192.168.1.100", "port": 9099}
```

### 第三步：查看与分析流量

抓到的请求会实时显示在列表中：

- 点击任意请求查看详情：Headers / 请求体 / 响应体 / 时间线
- 顶部搜索框支持 URL 关键字、方法、状态码、域名、时间段组合过滤
- 长按（移动端）或右键（桌面端）请求可以进行复制、重放、导出等操作

## 常用功能速览

| 功能 | 入口 | 用途 |
|------|------|------|
| 请求重放 | 右键/长按菜单 | 修改后重新发送请求，验证接口行为 |
| 重写规则 | 设置 → 请求重写 | 重定向 URL、修改请求/响应 |
| 脚本 | 工具箱 → JavaScript | 用 JS 动态处理请求/响应 |
| 弱网模拟 | 设置 → 弱网 | 模拟延迟/丢包/离线/限速 |
| 断点调试 | 设置 → 断点 | 拦截请求/响应进行人工修改 |
| 批量操作 | 多选模式 | 批量导出/删除/重放 |
| API 端点 | 工具箱 → API 端点 | 从流量中自动归纳 REST 接口 |
| 性能监控 | 工具箱 → 性能监控 | 连接池与请求耗时仪表盘 |
| 开发工具 | 工具箱 → 开发工具 | Cron 表达式 / JWT 解码 / UUID / SHA 哈希 |
| AI 分析 | 设置 → MCP Connection → AI 分析 | AI 对话分析抓包数据（支持 Agent 模式自动查询） |
| 使用文档 | 设置页底部 / 工具箱 | 内置全部功能教程与开发文档（离线可用） |

## 可选增强

- **QUIC 拦截**（Android）：偏好设置 → 「自动开启抓包」下方开关，丢弃 UDP:443 强制应用回落 TCP，使游戏类 App 流量也可抓包
- **双向认证 mTLS**：偏好设置中配置客户端证书，访问要求双向 TLS 的服务时使用
- **莫奈取色**（Android 12+）：主题与启动页自动跟随壁纸配色
- **自定义启动页**：偏好设置 → 启动页，可切换渐变品牌页/自定义图片并自定义时长与小字；「跟随主题」模式背景与文字随主题/深浅模式变化（推荐）
- **MCP 自动化**：定时任务（支持 Cron）、事件监听、规则引擎、工作流——把重复的调试动作交给 AI

## 平台支持边界

抓包能力受系统权限模型限制，这几件事先说清楚，省得白折腾：

| 场景 | 现状 | 原因 / 替代做法 |
|---|---|---|
| **Mac App Store 应用**（上游 #874） | 抓不到 | App Store 分发版运行在沙箱里且被强制签名校验，系统代理对其无效。要接管必须走 Network Extension / TUN，需要开发者签名与授权（本仓是未签名构建，做不了）。替代：用同一 App 的非商店版（官网/dmg 版），或换支持 TUN 的工具 |
| **鸿蒙 HarmonyOS**（上游 #683） | 暂未提供构建 | 需要单独的 HarmonyOS 工程 + Flutter 的 ohos 分支工具链，属独立移植工作。替代：用 Android 版跑在兼容层（若设备支持），或把手机流量交给另一台设备上的代理 |
| **Linux arm64**（上游 #560） | CI 中已尝试构建 | 依赖 Flutter 对 Linux arm64 桌面的工具链；arm64 runner 上装不到 SDK 时会自动跳过该架构（不影响 amd64 产物）。也可自行 `flutter build linux --release` |
| **QUIC / HTTP3 内容**（上游 #489） | 只做拦截与识别，不做内容解密 | 完整解密 1-RTT 需要 TLS1.3 握手状态机与密钥调度，工程量极大。当前策略：开启「拦截 QUIC」让应用回落到 TCP HTTP（内容即可正常抓），QUIC 会话页列出识别到的连接与 SNI |
| **Windows 上自带网络栈的进程** | 需分层接管 | 见「常用功能技巧」的 Windows 全局接管一节（WinHTTP + 环境变量；仍不行则把 ProxyPin 挂到支持 TUN 的工具下） |
| **Flutter 应用抓不到 HTTPS**（上游 #860） | 抓不到 | Dart 运行时自带一份根证书列表，**不读系统 CA**，所以装了 ProxyPin 证书也没用。需要在应用侧信任该 CA，或改抓其原生网络库的调用 |
| **想找旧版本安装包**（上游 #881） | 从 Releases 取 | 本仓每次发版都保留全部产物，进入 Releases 页面按版本号（tag）即可下载对应的 apk / ipa / deb / zip |
| **抓不到却不知道卡在哪** | 用「抓包自检」 | 工具箱 → 「抓包与重放」→ **抓包自检**：只读检测代理服务、系统代理、CA 证书、最近流量，并列出常见原因与对策 |
