# 扩展与定制指南

> 上游 #872 的诉求是"插件接口"：希望使用者能自由定制、升级后也方便迁移。
> ProxyPin 已经有一套**分层扩展点**——不需要改动应用本体，就能把"抓包 → 改写 → 上报 → 自动化"串成自己的流程。这份文档把可用手段、组合方式和边界一次讲清。

---

## 1. 扩展点全景

| 层级 | 手段 | 能做什么 | 入口 |
|---|---|---|---|
| 流量改写 | **请求重写规则** | 改 URL / 请求头 / 请求体 / 状态码 / 响应头 / 响应体，支持正则分组 `$1`、环境变量 | 设置 → 请求重写 |
| 逻辑编排 | **JS 脚本** | `onRequest` / `onResponse` / `onWebSocket` 钩子，可 `require()` 第三方库、读环境变量、日志出图 | 设置 → 脚本 |
| 参数注入 | **环境变量** | 多环境变量 + 内置变量（`{{timestamp}}`、`{{uuid}}` 等），任意支持 `{{name}}` 的位置可用 | 设置 → 环境变量 |
| 批量配置 | **采集方案** | 一键批量启停一组规则（域名过滤 + 脚本 + 重写 + Mock 场景） | 工具箱 → 采集方案 |
| 对外能力 | **MCP Server** | 把抓包能力暴露成标准 MCP 工具/资源，供 LLM 或 IDE 直接调用 | 设置 → MCP |
| 自动化 | **工作流编排** | 定时（Cron）/ 事件触发 / 规则引擎，把重复动作交给机器 | 设置 → MCP 自动化 |
| 数据出站 | **上报服务器 / 导出** | 把流量推到外部服务；导出 HAR / cURL / Python / Fetch 片段 | 请求右键、设置 → 上报服务器 |
| 免改造诊断 | **抓包自检 / QUIC 会话 / 安全自检** | 只读诊断与元数据视图，不改系统设置 | 工具箱 |

> 一句话：**要拦截逻辑写脚本，要固定动作写重写规则，要批量管理用采集方案，要接 AI 用 MCP，要定时用工作流。**

---

## 2. 各扩展点怎么用

### 2.1 脚本（最接近"插件"的形态）

```javascript
async function onRequest(context, request) {
  // 动态签名、加解密、加时间戳、切换环境域名……
  request.headers['X-Sign'] = sign(request);
  return request;
}
```

- 支持 `require(url)` 加载任意 CommonJS 风格 JS 库（走引擎内置网络栈，不受抓包代理影响）；
- 脚本里可以用 `context.env` 读环境变量，日志面板支持直接渲染图片（二维码等）；
- 脚本出错**不会让请求失败**：会记录告警并按原样放行（这一点很关键，避免"上了脚本整站打不开"）。

### 2.2 MCP：把抓包能力交给 AI

MCP Server 把常用能力包装成工具，LLM / IDE 可以直接：读取会话与请求详情、下发/调整重写与脚本规则、触发抓包启停、跑安全基线核查等。

其中 **`diagnose_capture`** 是「抓包自检」的 MCP 版本：返回代理服务是否在跑、系统代理是否指向本应用、CA 证书是否受信任、最近是否真有流量，并附带可执行建议。**用户说"抓不到包/页面打不开"时，让 AI 先调这个工具**再下结论。

- 默认**只监听 `127.0.0.1`**；需要局域网访问时显式开启（开启后无鉴权，谨慎）；
- 与「工作流编排」组合，就是一套**事件驱动的自动化**：定时拉取、事件触发、规则引擎三件套。

### 2.3 采集方案：把一组配置打包成一个开关

一个"方案"= 域名过滤 + 关联脚本 + 重写规则 + Mock 场景，一键 apply / 撤销。适合：
- 按项目切换调试环境（测试 / 预发 / 生产）；
- 把"某次排查用到的全部改动"固化下来，下次一键复用（比手工记规则清单可靠）。

### 2.4 环境变量 + 内置变量

`{{token}}`、`{{host}}` 这类自不必说；内置变量不需要定义即可用：
`{{timestamp}}`、`{{timestamp_ms}}`、`{{datetime}}`、`{{date}}`、`{{time}}`、`{{unix_date}}`、`{{uuid}}`。
环境变量页右上角的 ⚗ 按钮可以列出并一键复制。

## 3. 三个组合示例

**例 1：给某接口动态签名并留存证据**
1. 环境变量里放 `{{secret}}`；
2. 脚本里读出来算签名，写进请求头；
3. 需要留证时用「手动 Fuzz」跑变体，结果导出 CSV/JSON。

**例 2：把线上流量镜像给自建分析服务**
1. 「上报服务器」配置目标地址；
2. 「采集方案」限定域名范围，避免把无关流量推出去；
3. 用「安全自检」对已抓流量做被动核查（只读、不发请求）。

**例 3：让 AI 帮忙排查"某个接口偶尔 500"**
1. 开「抓包自检」确认链路正常；
2. MCP 接上 LLM，让它读会话列表与响应体；
3. 发现问题后，让它下发一条重写规则做临时 Mock，或生成脚本复现。

## 4. 边界（为什么不做"动态加载二进制插件"）

- **签名与分发**：本仓是未签名构建，加载第三方动态库会引入无法审计的代码，且各平台（macOS 公证、iOS 沙箱、Android SELinux）限制不同；
- **升级迁移**：脚本、规则、环境变量、采集方案都是**文本配置**，天然可版本管理、可 diff、可跨设备迁移（配置管理支持文件与剪贴板导入导出）；
- 所以这条路线的选择是：**扩展逻辑用文本（脚本/规则/配置），能力出口用标准协议（MCP）**——升级后你的定制不会失效，也不需要在应用里开一个"任意代码执行"的口子。

> 如果你的场景确实需要原生插件（例如自定义协议解析、专有加解密硬件），可以在 issue 里描述具体需求，我们再看是否值得引入受控的扩展机制。
